 1. Project Overview
 A customer messages the hotel on WhatsApp, asks for the menu, orders food, chooses delivery or dine-in, and
 picks Cash on Delivery or online payment. The owner sees the order instantly on a dashboard (and by email),
 accepts it, and passes it to the kitchen and the rider. Every status change sends the customer a WhatsApp
 update. One system serves many hotels (multi-tenant).

 1.1 Goals
  • 24/7 instant customer replies in English, Arabic or Roman Urdu.
  • Owner sees each order with customer name, number, payment type, screenshot and address, and gets an
    alert immediately.
  • Separate screens for owner, manager, chef and rider.
  • One codebase and one database for all hotels, with strict data isolation.
  • Premium, calm, professional look. No flashy gradients, no clutter.
  • Free tools to start, with a clear upgrade path when clients grow.

 4.1 Order data flow
  • Customer writes. Meta calls the webhook. Express verifies the signature, saves the message (unique
    wa_message_id), queues a job, returns 200 OK.
  • The worker finds the hotel from phone_number_id, loads the customer's conversation state and language, and
    decides the next reply.
  • The bot sends the reply through the WhatsApp API in the customer's language.
  • When the order is confirmed it is saved in orders and order_items.
  • The server pushes a live event (SSE) to the dashboard, sends Web Push, and queues the owner email.
  • The owner presses Accept. Status changes, the customer gets a WhatsApp update, and the kitchen and rider
    screens update.

 7. Design System
 This section is the single source of truth for how the dashboard looks. Build the UI from it, and any new screen
 should follow it without guessing.

 7.1 Design principles
  • Calm and premium: a dark midnight base, soft white surfaces, and gold used sparingly.
  • Minimal: thin borders, light shadows, generous spacing. No gradients, glows, neon, or decorative blobs.
  • Classic: restrained type, a serif only for the brand name and login heading.
  • Operational first: restaurant staff are busy. Large tap targets, clear status colors, readable on a phone in a
    bright kitchen.
  • One accent: gold means 'important or active'. If everything is gold, nothing is.

 Item                     Design

 Password                 bcrypt hash (cost 10 to 12). Never stored in plain text.

 10.6 Scalability, Helmet and tenant isolation
  • Stateless servers: sessions and bot state live in the database or Redis, so more servers can be added behind
    a load balancer.
  • Light webhook: verify, save, queue, return 200. All real work runs in workers.
  • Cache: hotel settings and menu in Redis.
  • Helmet: one line in Express that sets secure HTTP headers (blocks clickjacking, content sniffing and similar
    browser-side attacks).
  • Tenant isolation: a hotel's staff must never see another hotel's data. Every repository query filters by
    restaurant_id taken from the token, PostgreSQL Row Level Security is added as a second lock, and automated
    tests try to read across hotels and must fail.
  • Pooling: use the connection pooler from Neon or Supabase, or PgBouncer.

 11.2 Maintenance
  • Retention: delete or archive raw messages after about 90 days. Keep orders much longer.
  • Partitioning: split the messages table by month only when it reaches many millions of rows. Not needed at the
    start.
  • Backups with pg_dump: a PostgreSQL tool that writes the whole database to a file. Example: pg_dump -Fc
    mydb > backup.dump, restored with pg_restore. Run it daily, store the file in cloud storage, and test a
    restore.
  • Privacy: screenshots in private storage with expiring links, a way to delete a customer's data, minimal logging
    of personal data.


 12. WhatsApp Bot Conversation Flow
 FIRST MESSAGE -> LANGUAGE (English / Roman Urdu / Arabic)
   -> MENU -> CART -> ORDER_TYPE (delivery / dine-in) -> ADDRESS -> PAYMENT_METHOD
                                                             |
              COD ------------------------------------------+--> CONFIRMED
              ONLINE -> AWAITING_SCREENSHOT -------------------> CONFIRMED (payment pending check)
 CONFIRMED -> owner actions -> status messages to the customer
 Any state -> HUMAN (customer asks for an agent, or the owner replies from the Business app)

  • Interactive lists and buttons first, free text as a convenience.
  • Every step offers 'Cancel' and 'Talk to agent'.
  • Outside opening hours the bot replies with the hotel's hours, using the hotel's timezone.
  • Online payment: the bot sends the hotel's account number and asks for a screenshot. The bot cannot verify it,
    the owner confirms in their bank or wallet app and presses Verified.
  • If the owner replies directly (Coexistence mode), the bot pauses for that customer (human_until).
  • Delivery area and minimum order checks.
  • Never send marketing messages without the customer's consent.

 15. Security Checklist
  • Verify X-Hub-Signature-256 on every webhook POST.
  • Secrets (app secret, verify token, JWT secret) only in environment variables. Never commit .env.
  • WhatsApp access tokens encrypted in the database.
  • restaurant_id filter on every query, Row Level Security, and cross-tenant tests.
  • bcrypt passwords, short access token, rotating refresh token, httpOnly cookies.
  • Zod validation on all input. ORM prevents SQL injection.
  • helmet, CORS limited to your domains, HTTPS everywhere.
  • Rate limiting on login, APIs and each customer number.
  • Screenshots in private storage with expiring links.
  • Do not log passwords, tokens or full phone numbers (mask them).
  • Keep dependencies updated (npm audit, Dependabot).
  • Tell owners: the screenshot is only a hint, always confirm the money in the bank or wallet app.

 16. Glossary
 Term                                Plain explanation

 pnpm                                A package manager like npm, faster and better at monorepos.

 Docker Desktop                      App that runs small isolated 'containers'. We use it to run PostgreSQL and Redis without
                                     installing them.

 docker compose                      One file (docker-compose.yml) that describes several containers, started together with one
                                     command.

 Tunnel (ngrok, Cloudflare           Gives your local server a temporary public HTTPS address so Meta can call your webhook
 Tunnel)                             during development. Not needed in production.

 Webhook                             A URL on your server that Meta calls whenever a WhatsApp message arrives.

 Helmet                              Express middleware that sets protective HTTP headers.

 Tenant / multi-tenant               A tenant is one customer (a hotel). Multi-tenant means many hotels share one system,
                                     each seeing only its own data.

 Tenant isolation                    The guarantee that one hotel can never read or change another hotel's data.

 Zustand                             A small global state library. Components read shared state directly, with no prop drilling.

 TanStack Query                      Fetches and caches server data and tracks loading and error states.

 Narrow selector                     Reading only the exact piece of state you need so the component re-renders only when
                                     that piece changes.

 Pagination                          Loading data in small pages (for example 20 rows) instead of all at once.

 Virtualization (TanStack Virtual)   Rendering only the rows visible on screen for very long lists.

 BullMQ                              A job queue. The webhook drops work into the queue and workers process it, with retries.

 SSE (Server-Sent Events)            A one-way live connection from server to browser, used for instant new-order updates.

 PWA                                 Progressive Web App: a website installable on the phone home screen that can send
                                     notifications.

 JWT                                 A signed token that proves who is logged in.

 RTL                                 Right-to-left layout, needed for Arabic.

 i18n                                Internationalization: translating the interface and formatting numbers and dates per
                                     language.

 pg_dump                             PostgreSQL tool that exports a database into a backup file.

 Retention                           A rule for how long old data is kept before deleting or archiving it.

 Coexistence                         Meta feature letting one number run on the WhatsApp Business app and the Cloud API at
                                     once.
